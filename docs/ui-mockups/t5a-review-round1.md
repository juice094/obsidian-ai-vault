# T5a Mockup 评审（第 1 轮 · 2026-07-30）

**对象**：`docs/ui-mockups/t5a-mobile-input-dock-mockup.html`（四屏 + 注记层）
**结论：不通过，按下列意见修改后复审。** 修订 3 交互模型整体执行到位
（零新增列表 UI、callout 即气泡、输入坞唯一新增元素），visual fidelity 好。
两条阻断级语义缺陷必须先解决——它们直接决定 W4 实现写出来的行为对错。

## 阻断级（不修复不得进 W4）

### B1. 「发送写到哪里」的语义是错的（屏2 注记层）

屏2 注记写「发送：append `> [!user]` 到**当前 md**」。当用户正在看的是
**普通笔记**（如《旅行预算表.md》）时，发送会把聊天内容写进用户的笔记——
这是不可接受的破坏性行为。正确语义：

- 当前打开的是**会话笔记**（`AI 会话/` 下）：发送 → 写入当前 md。✓
- 当前打开的是**普通笔记**：发送 → 自动创建新会话 md（上下文 chip 内容作为
  首条 user 消息前缀）**并跳转到该会话笔记**，流式在那里进行。
- 屏2 注记层必须把这条分支语义写死，W4 按此实现。

### B2. 上下文 chip 自指问题（屏2）

mockup 里查看的正是会话笔记《syncthing 冲突处理》，chip 却挂着
「📎《syncthing 冲突处理》」——把整个会话（含本问题）当自己的上下文，逻辑循环。规则：

- 查看**普通笔记**时：chip = 该笔记（默认开）。✓
- 查看**会话笔记**时：chip **不出现**（或显示为禁用态「上下文：本会话」）。
- 注记层补这条规则。

## 细节（逐条修改，不阻塞复审标准但都要改）

- D1. 屏1 未画 Obsidian 原生底部工具栏（真机存在，高约 90px）。
  注记层补一条：FAB 与输入坞 bottom offset 必须避让原生底部栏，参数写进注记。
- D2. 屏2「Model [pill] expert」双态表达歧义（pill 在 on 态指 expert 还是指开关开？）。
  改为分段控件 `default | expert` 两态点选。
- D3. 屏4「归档」文件夹来源未定义——加注记：**纯手动归档**（用户长按移动），
  无自动归档逻辑。防止 W4 过度实现。
- D4. 屏3 注记补一条坞的状态机：发送后坞自动收起为「正在生成…」条，
  turn 完成（或中断）后恢复为展开坞（输入框保持聚焦）。
- D5. 屏1 的 `[!user]` callout 标题显示为字面 `[!user]` 与真实渲染不符
  （Obsidian 会把 type 首字母大写渲染为 "User"）。**指挥层已批准微格式调整**：
  md 格式允许 callout type 后带显式标题（如 `> [!user] 你`），
  解析器按 type token 识别、忽略标题文本。W4 实现时同步检查 T2 解析器
  是否按整行匹配，是则放宽；mockup 里标题改画为「你」。
- D6. 图例（legend）只有 原生/注入 两个点，注记实际用了三种徽标（含「交互」），
  图例补上交互项。
